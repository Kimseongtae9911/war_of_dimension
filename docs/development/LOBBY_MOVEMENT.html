1. 결과

128명의 입력 처리율을 유지하면서 CPU와 패킷 대기 p99 상한을 줄였다. CPU 감소에는 빈 타이머 반복 제거의 영향이 크다.

128명 유지 검사 끝 대기는106→131개로 늘었고, 이후 정리를 확인했다. 본인 이동 응답은 유저당 평균 2.18→3.36개/s다. 입력 즉시 응답도 포함하므로 실제 좌표 변화율은 아니다. 최대 동접·66.7Hz 유지·화면 품질 개선을 입증한 결과는 아니다.

2. 원인

이동 갱신이 끝나자마자 자신을 다시 큐에 넣었다. 1ms 미만 작업도 반복됐고, 빠른 이동→정지→이동 입력은 갱신 체인을 두 개 만들 수 있었다.

// 이전 흐름 · 개념 코드
MovePacket: 이전 방향 == 0 → 갱신 U1 추가
move → stop → move가 먼저 처리됨 → 갱신 U2도 추가
U1 실행 → U3 / U2 실행 → U4 ...
타이머 빈 큐 → yield 반복

체인 중복은 코드 흐름으로 확인한 경로이며 기존 체인 수를 직접 계측한 결과는 아니다. 초기 이동 시각과 동일 shared_mutex 중첩 잠금도 함께 수정했다.

3. 해결 방식

유저당 예약/실행 대기 하나만 유지한다. 타이머는 위치를 수정하지 않고 기존 FIFO에 generation 보호 작업을 넣는다.
