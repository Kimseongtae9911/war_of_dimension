2. 분석한 원인

기존 FIFO 큐는 callback마다 게시 mutex를 획득했다. 생산자와 소비자가 같은 잠금을 반복 사용한다. 측정은 경합 부하에서 처리량 증가를 보여주지만, 잠금별 대기 시간은 직접 수집하지 않았다.

for (작업 예산) {
  lock(게시 mutex);
  job = queue.pop();
  unlock(게시 mutex);
  job.Execute();
}

3. 해결 방식

실행 대기열이 빌 때만 소유권을 교환한다. FIFO·Five/Snapshot·예외 이후 남은 작업·Clear·callback 직렬성은 유지한다.

if (실행 대기열.empty()) {
  lock(게시 mutex);
  swap(실행 대기열, 게시 대기열);
}
job = 실행 대기열.pop();
job.Execute();
