미니언 Update는 1매치 tick CPU cycle의 81.8%. 아래 세부 구간은 부모 내부 비용이므로 서로 중복 합산하지 않는다.

2. 분석한 원인

플레이어·미니언 이동 → NavMesh 검색 → HeightMesh 검색 → 다음 tick에서 반복

3. 해결 방향

이번 변경은 계측과 분석이다. 지형 검색 최적화와 중복 송신 수정은 아직 적용하지 않았다.

우선: 지형 검색 후보 축소

// 후속 설계 의사 코드 · 미구현
candidates = xzGrid.Query(ray.origin);
SortByOriginalTriangleOrder(candidates);
for (triangle : candidates) {
    if (ExistingRayTest(triangle, ray))
        return ExistingHitResult(triangle);
}

유지할 판정 계약

수직 Ray의 공간 후보를 줄이고 정적 삼각형 계산을 사전 저장한다. 기존 첫 hit 순서·높이 필터·일반/스킬 판정 차이를 보존해야 한다.

NavMesh는 현재 노드/주변 후보를 우선 활용하는 방식을 검토한다. 정지 상태 캐시는 위치·지형 세대·강제 이동의 무효화 조건부터 정해야 한다.

다음 단계: 동일 좌표/경계/실패/스킬 Ray 판정 회귀 → 같은 시나리오 5회 전후 비교 → tick·CPU·이동/NPC 동작 확인.

1매치 계측 끔 → 켬: tick 20.34 → 20.27ms, CPU 7.67 → 7.65%. 각 5/5회, 같은 seed 순서 교차.

계측 끔도 같은 계측 코드가 포함된 실행 파일이다. 원본 main 바이너리 대비 비활성 분기/카운터 코드 비용은 별도 미측정. 다중 매치는 NPC 나이·활성 수와 방문 삼각형 수도 달라진다. tick 시간 증가를 worker 경합만으로 설명하거나 순수 매치 수 확장 비율로 해석하지 않는다.
